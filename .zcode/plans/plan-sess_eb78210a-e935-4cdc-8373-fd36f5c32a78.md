## M1 — Autorisation par jeton signé sur la reprise de paiement (1 helper neuf + 4 edits)

Le bouton "Réessayer le paiement" appelle l'action serveur publique `retryCheckoutSession({resumeType, resumeId})` **sans aucune preuve d'identité ni de propriété** → on peut lire le `pickupCode` et spammer n'importe quel client via son cuid. Comme il n'y a **pas de session** au moment du resume, on ne peut pas utiliser `auth()`+propriété. Fix = jeton HMAC.

1. **Nouveau `lib/resume-checkout-token.js`** (modelé sur `lib/stripe-oauth.js`) :
   - `createResumeCheckoutToken({resumeType, resumeId, email})` → `base64url(JSON{purpose:"resume-checkout", resumeType, resumeId, email, nonce, exp}).hmac`, TTL 30 min, secret `AUTH_SECRET` (fail-hard comme `lib/autologin.js:3-12`).
   - `verifyResumeCheckoutToken(token, {resumeType, resumeId})` → `{ok, email}` ou `{ok:false}` via `timingSafeEqual`, vérifie purpose/exp/signature + correspondance `resumeType`/`resumeId`.

2. **`actions/shared/resume-checkout-after-verification.js`** — `retryCheckoutSession({resumeType, resumeId, resumeToken})` exige et vérifie `resumeToken` (fail-closed) **avant** de dispatcher. Le jeton signant `(resumeId,email)` et n'étant émis qu'après e-mail vérifié, c'est la preuve de propriété.

3. **`actions/auth/verify-email.js`** :
   - Remplacer l'appel inline `retryCheckoutSession(...)` (ligne 176) par un appel **direct** aux builders sous-jacents (`resumeOrderAfterVerification` / `createWorkshopReservationCheckoutSession` / `createFormationReservationCheckoutSession`) — le chemin serveur déjà-sûr n'a ainsi **pas besoin de jeton**.
   - Minter un `resumeToken` via `createResumeCheckoutToken({resumeType, resumeId, email: matchedToken.email})` et le renvoyer dans le résultat de l'action (pour que le bouton de retry manuel le transmette).

4. **`app/(auth)/verify-email/page.js`** (lignes ~50-51) — passer `resumeToken` du résultat vers les props du formulaire.

5. **`app/(auth)/verify-email/verify-email-form.js`** (handler `handleRetryPayment` ligne ~54) — accepter `resumeToken` en prop, le soumettre avec `{resumeType, resumeId, resumeToken}`, masquer/désactiver le bouton si absent.

Note: le `pickupCode` dans l'URL de succès (`orders.js:630`) reste — il n'est désormais renvoyé qu'au propriétaire prouvé, c'est le "ticket de retrait" légitime de l'acheteur.

## H2 — Lire l'IP réelle (hop de droite), pas le hop falsifiable (1 fichier)

Topo confirmée : **1 seul reverse proxy Nginx** devant le process Next.js. Le client réel est l'entrée la plus à **droite** du `X-Forwarded-For` (celle qu'ajoute Nginx via `$proxy_add_x_forwarded_for`).

**`lib/rate-limit.js`** `getClientIp()` (lignes 27-32) :
- Prendre la **dernière** entrée non vide de `x-forwarded-for` au lieu de `split(",")[0]`.
- Fallback `x-real-ip`, puis `"unknown"`.
- Commentaire documentant l'hypothèse "1 proxy Nginx" + la marche à suivre si un CDN (Cloudflare) est ajouté devant (utiliser une allowlist d'IPs de proxy / un hop-count explicite).

Ceci restaure l'efficacité réelle des limiteurs sur login / forgot-password / reset / verify-email / register.

*(Durcissement optionnel non inclus pour rester minimal : keyer aussi les buckets d'auth sur le hash de l'e-mail seul, pas seulement `${email}:${ip}`. Je peux l'ajouter en suivi.)*
